# ClaudeGlow — инструкции для Claude

Поведение, статусы и файлы — в `README.md`, прочитать перед правкой. Здесь только правила работы.

## Сборка

- Штатный `csc.exe` .NET Framework 4.8, **C# 5**: нет `$"..."`, `?.`, `nameof`, `=>`-членов,
  инициализаторов авто-свойств, `out var`.
- Собирать `build.cmd nostart`. Без `nostart` вызов из Bash висит, пока программа запущена.
- Репозиторий и установленная копия (`%LOCALAPPDATA%\Programs\ClaudeGlow`) — разные папки. Сборка
  трогает только свой `ClaudeGlow.exe`: занят — переименовывается в `ClaudeGlow.old.exe`. Установленный
  экземпляр обновляется установщиком. Два ClaudeGlow сразу не запустить: второй выходит по мьютексу.

## Проверка

- Синтетические события — curl на `127.0.0.1:47651/hook` (пример в README), результат —
  `%LOCALAPPDATA%\ClaudeGlow\log.txt`.
- Хуки в `~/.claude/settings.json` действуют на **все** сессии, включая рабочие треды пользователя.
  Не ломать их формат; проверять JSON после правки. Файл может быть симлинком — запись идёт в цель.
- `ClaudeHooks` проверять на копии `settings.json` через `CLAUDE_CONFIG_DIR`: снять → поставить →
  сравнить набор хуков и остальные ключи с исходником (порядок групп внутри события может смениться).
- Скриншоты README (`docs\*.png`) — обвязкой на синтетических данных, без реальных путей и имён.
- Протокол OpenRGB проверять python-скриптом в scratchpad до переноса в C#.

## Правила кода

- Комментариев нет, один класс — один файл, `if/else` вместо `switch` на две ветки.
- Ресурсы: таймеры не чаще раза в секунду (сейчас 5 с — живость и переподключение, 15 с — таймауты),
  запись в OpenRGB только при смене эффекта. Исключение, согласованное с пользователем, — кадры
  плавной пульсации (40 мс), и только пока горит пульсирующий статус.

## Грабли

- Heredoc в Bash ест обратные слэши — `.cmd` и строки с `\` писать инструментом записи или python-скриптом.
- `.cmd` — CRLF и только ASCII; соседние скрипты и сам `.cmd` вызывать полным путём.
