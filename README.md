# AgentGlow

Трей-сервис: показывает подсветкой RGB-устройств (видеокарта, лента, мышь — всё, чем управляет
[OpenRGB](https://openrgb.org)), что делают ИИ-агенты на компьютере. Глянул на подсветку — понял, нужно ли
разворачивать окно: агент работает, закончил, задал вопрос, ждёт разрешения или упёрся в ошибку.

Работает с [Claude Code](https://claude.com/claude-code) и [OpenCode](https://opencode.ai) из коробки, а любое другое
приложение подключается без кода — одним HTTP-запросом (раздел «Как подключить приложение»). Подсветка одна на
всех: цвета и эффекты задаются на статус, а не на приложение, поэтому «Ошибка» выглядит одинаково, кто бы её ни
вызвал.

**Актуальная версия** — на странице [Releases](../../releases/latest), что изменилось — в [истории версий](CHANGELOG.md).
До версии 2.0 программа называлась ClaudeGlow и умела только Claude Code.

![Меню в трее](docs/tray-menu.png)

Claude Code — в терминале, в десктопном приложении (вкладка Code) и в расширениях редакторов, везде, где он читает
`~/.claude/settings.json`. OpenCode — десктоп, терминал, `opencode serve`, везде, где он читает плагины из
`~/.config/opencode/plugins`.

## Установка

1. Поставь [OpenRGB](https://openrgb.org) и включи в нём SDK-сервер (вкладка SDK Server → Start
   Server, порт `6742`). Удобнее всего — службой Windows или с ключом `--server` в автозапуске.
2. Скачай `AgentGlowSetup.exe` со страницы [последней версии](../../releases/latest), запусти и
   подтверди окно UAC.
3. Проверь папку установки (по умолчанию `C:\Program Files\AgentGlow`) и отметь, что подключать:
   - **Claude Code: прописать хуки** — установщик добавит хуки AgentGlow в `~/.claude/settings.json`, ничего
     другого в файле не меняя (копия прежнего файла — `settings.json.claudeglow.bak`);
   - **OpenCode: подключить плагин** — файл `agentglow.js` ляжет в `~\.config\opencode\plugins`, настройки
     OpenCode не меняются.

   Можно отметить одно из двух или оба. Снял отметку при повторной установке — интеграция снимается.
4. Нажми «Установить». Программа запустится (без прав администратора), в трее появится кружок. **Перезапусти
   Claude Code и OpenCode**: хуки и плагины читаются при старте.

![Установщик](docs/setup.png)

Интеграции можно подключить и позже: меню трея → «<приложение> не подключён — подключить».

## Отчёты о сбоях

В установщике есть галочка «Отправлять автору отчёты о сбоях», по умолчанию она **выключена**.

- **Что уходит.** Версия программы, Windows и .NET, текст ошибки, последние 100 КБ журнала
  `%LOCALAPPDATA%\AgentGlow\log.txt`: названия событий и инструментов агентов, короткие номера сессий и
  процессов, имена папок проектов, пути к настройкам Claude Code и плагину OpenCode с именем пользователя
  Windows, названия RGB-устройств. Тексты запросов, ответы и код агентов в журнал не попадают. Сервер записывает
  IP-адрес, с которого пришёл отчёт.
- **При каких сбоях.** Программа упала.
- **Куда.** `https://aokazantsev.ru/pets/agentglow/crash-report`, сервер в России. Отчёты видит только автор,
  хранятся последние 50 МБ — при поступлении новых самые старые удаляются. Подробности — в
  [политике обработки данных](https://aokazantsev.ru/privacy).
- **Когда.** Один раз при сбое, без повторных попыток. Не ушло — в журнал пишется «отчёт о сбое не
  отправлен» с причиной.
- **Как изменить выбор.** Переустановить программу с галочкой или без неё. Деинсталлятор удаляет
  согласие вместе с остальными данными.

## Обновление

Трей → «Проверить обновление…». Есть версия новее — установщик скачивается в «Загрузки» и
открывается в Проводнике; путь к нему и кнопка «Открыть папку» остаются в окне. Запусти его — новая
версия встанет поверх текущей, удалять старую не нужно, настройки сохранятся. Если сбой вызван
настройками, в установщике есть галочка «Сбросить настройки». После обновления перезапусти агентов, если в
версии менялись хуки или плагин.

## Удаление

«Параметры → Приложения → AgentGlow → Удалить» или `Uninstall.exe` в папке программы. Программа
закрывается сама; снимаются хуки AgentGlow из настроек Claude Code и плагин OpenCode (чужие хуки и плагины не
трогаются), удаляются программа, настройки, журнал, автозапуск и запись в «Приложениях».

## Настройки

![Настройки](docs/settings.png)

Для каждого статуса — эффект, цвет и скорость, кнопка «Проверить» показывает эффект 5 секунд. Настройки общие
для всех приложений. Ниже — какие устройства участвуют в индикации и какие держат постоянный свет.

Какие источники событий включены — ключ `sources` в `settings.txt` (`claude,opencode,generic`); его выставляет
установщик. Выключенный источник не принимает события и не показывает проблем в трее.

## Как устроено

1. Программа слушает один порт `127.0.0.1:47651` и раскладывает запросы по адресу на **источники**:

   | Адрес | Источник | Кто шлёт |
   |---|---|---|
   | `/hook` | Claude Code | HTTP-хуки Claude Code (`type: "http"`) из `~/.claude/settings.json` |
   | `/opencode` | OpenCode | плагин `agentglow.js` внутри OpenCode |
   | `/status` | другие приложения | всё, что умеет отправить HTTP-запрос |

   Все пути принимаются только с заголовком `Host` `127.0.0.1:<порт>` или `localhost:<порт>`, а `/opencode` и
   `/status` — ещё и только с заголовком `X-AgentGlow: 1`, поэтому обычная веб-страница в браузере подсветку
   дёрнуть не может. Размер запроса ограничен: 64 КБ для `/opencode` и `/status`, 64 МБ для `/hook` (хуки Claude
   Code несут содержимое файлов).
2. Каждый источник ведёт свои треды (сессии) и приводит их состояние к общему набору статусов. Итоговый цвет —
   самый важный статус среди **всех** тредов **всех** источников.
3. Подсветкой управляет OpenRGB через SDK-сервер (`127.0.0.1:6742`, протокол версии 3).

## Статусы (по убыванию важности)

| Статус | Claude Code | OpenCode | По умолчанию |
|---|---|---|---|
| Ошибка | `StopFailure` (ошибка API, лимит, сеть) | `session.error` (кроме Esc), повторы запроса `session.status: retry`, падение сервера OpenCode | бегущая строка, красный, скорость 4 |
| Нужно разрешение | `Notification` / `permission_prompt` | `permission.asked` до `permission.replied` | бегущая строка, пурпурный `#FF00FF`, 4 |
| Задал вопрос | `PreToolUse` для `AskUserQuestion`, `elicitation_dialog` | `question.asked` до `replied` / `rejected` | бегущая строка, оранжевый, 4 |
| Закончил, жду больше минуты | «Закончил» дольше 60 с (свой таймер) | то же | плавная пульсация, зелёный, 1 |
| Закончил | `Stop` | `session.status: idle` после работы | ровный зелёный |
| Работаю | `UserPromptSubmit`, `PostToolUse`, фоновые задачи | `session.status: busy` | ровный синий |
| Нет активных сессий | ни одного живого треда | то же | выключено |

**Закончил + Работаю.** Если самый важный статус — «Закончил» (или «жду больше минуты»), а другой
тред — любого приложения — при этом работает, карта делится: первая половина светодиодов — цвет «Закончил», вторая —
цвет «Работаю», ровным светом. Значок в трее тоже делится пополам. Статусы, требующие тебя (ошибка,
разрешение, вопрос), по-прежнему занимают всю карту. Деление работает, если у обоих статусов эффект с
цветом и у устройства есть режим Static с цветом на каждый диод.

### Claude Code

**Когда гаснет «Нужно разрешение».** События «разрешил» у Claude Code нет, а `PostToolUse` приходит
только после завершения команды — для долгой сборки это минуты. Поэтому раз в 5 с программа смотрит
на процесс треда: появилась новая дочерняя оболочка (`bash`, `sh`, `powershell`, `pwsh`, `cmd`) после
запроса — значит, разрешил и команда пошла, статус «Работаю». Отказ ловится хуком `PermissionDenied`.
Инструменты без дочернего процесса (правка файлов) и так завершаются за доли секунды. Оболочка не
говорит, чья она: если спросить мог не один исполнитель или за 5 минут до запроса и после него работали
другие агенты, эта проверка отключается, и статус снимается только событием самого вызова (`PostToolUse`,
`PostToolUseFailure`, `PermissionDenied`) — для долгой разрешённой сборки «Нужно разрешение» горит до её конца.

**Вопросы и разрешения при работающих агентах.** Тред может задать вопрос или ждать разрешения и
параллельно работать: агенты продолжают читать файлы и запускать команды. Их события приходят с тем же
`session_id`, но с полем `agent_id`. Поэтому «нужен ты» запоминается за исполнителем — основным тредом
или конкретным агентом — и снимается только его же событием: ответом на вопрос, следующим действием,
отказом (`PermissionDenied`), запуском разрешённой команды, а для основного треда ещё новым промптом и
концом хода. Работа других агентов вопрос не сбивает.

Запрос разрешения (`Notification` / `permission_prompt`) приходит без `agent_id` и без номера вызова,
даже когда спрашивает агент. Кто спросил, программа узнаёт из хука `PermissionRequest`: он приходит
перед каждой проверкой разрешения, с `agent_id`, но без `tool_use_id`; вызов узнаётся по агенту,
инструменту и `tool_input` — они совпадают с `PostToolUse` того же вызова. Незавершённые вызовы, проверка которых
началась за последнюю минуту, — кандидаты; «Нужно разрешение» горит, пока не завершится или не будет
отклонён каждый из них.

**Фоновые задачи.** Тред может закончить ход, оставив работать фоновые агенты, команды, воркфлоу или мониторы.
Claude Code перечисляет их в поле `background_tasks` события `Stop`: список не пустой — тред остаётся в «Работаю»,
таймаут «Работаю без событий» для него не действует. Задача закончилась — Claude будит тред, тот присылает новый
`Stop`, уже с пустым списком, — «Закончил». «Ошибка» снимается только новым промптом в этом треде.

Проверено в десктопном приложении (Claude Code 2.1.284): `permission_prompt` приходит ровно при показе
диалога разрешения; `idle_prompt` не приходит — поэтому «жду больше минуты» считает сама программа.

### OpenCode

OpenCode сам сообщает состояние сессии, поэтому догадок вроде «разрешил ли пользователь команду» здесь нет: на
запрос разрешения или вопроса приходит ответ-событие.

- Плагин `agentglow.js` живёт внутри OpenCode, подписан на события и пересылает на `127.0.0.1:47651/opencode` только
  вид события, номера сессий и запросов, папку проекта и номер процесса — без текстов запросов, ответов, команд и
  вопросов. Он ничего не читает у OpenCode кроме событий, не обращается к его серверу, перехватывает свои ошибки,
  не ждёт ответа дольше 1,5 с, после неудачной отправки молчит 10 с и не копит очередь (после 50 событий в ожидании
  отбрасывает «я жив», после 200 — всё). Если программа не запущена, OpenCode этого не замечает. Переменная
  `AGENTGLOW_DISABLE=1` отключает плагин целиком.
- **Тред** — главная сессия OpenCode. Сессии подагентов (инструмент `task`) учитываются в треде-родителе: их
  разрешения и вопросы горят, а «Работаю» и «Закончил» берутся только у главной сессии.
- **Ошибка.** Когда провайдер модели упирается в лимит или сбой, OpenCode сам повторяет запрос и ждёт — иногда
  часами. Пока идут повторы, горит «Ошибка»: она держится до времени следующей попытки плюс 20 с и гаснет сама,
  если запрос прошёл, или раньше — когда сессия закончила. Окончательная ошибка остаётся, пока в треде не начнётся
  новая работа. Прерывание по Esc ошибкой не считается: оно снимает висящие разрешения и вопросы.
- **Живость сессии.** Пока сессия работает, плагин раз в 20 с шлёт «я жив» (без содержимого) — для страховки
  «Работаю без событий».
- **Падение сервера OpenCode.** Серверная часть OpenCode (в десктопе — отдельный процесс внутри приложения) иногда
  падает молча: окно живо, а треды встали. AgentGlow следит за процессом сервера, номер которого приходит от
  плагина, и по коду выхода отличает падение от обычного закрытия. Упал (код выхода — ошибка Windows, например
  `0xC0000409`) — все треды этого сервера переходят в «Ошибку», а если их не было, в меню появляется строка «сервер
  OpenCode упал». Это значит: перезапусти OpenCode. Ошибка снимается, когда перезапущенный OpenCode пришлёт первое
  событие, или кнопкой «Сбросить статусы сессий». Обычное закрытие OpenCode треды просто убирает. В журнале —
  `opencode: server pid=… crashed, exit code 0x…`.
- В десктопе один процесс обслуживает все сессии OpenCode, поэтому закончившиеся сессии не пропадают с закрытием
  вкладки — ими занимается таймаут «Закончил».

## Когда тред считается закрытым

- Claude Code: пришёл `SessionEnd` или завершился процесс `claude.exe` треда (проверка раз в 5 с по номеру и времени
  старта процесса);
- OpenCode: сессию удалили (`session.deleted`) или завершился процесс OpenCode;
- другие приложения: событие `ended` или смерть процесса, если передан `pid`;
- страховки для всех (проверка раз в 15 с): «Работаю» без событий дольше `workingTimeoutMinutes` (30) → сброс;
  «Закончил» дольше `doneTimeoutMinutes` (120, 0 — никогда) → сброс; любой тред без событий 12 ч → удаляется.

Периодического «я жив» у Claude Code нет: тред, ждущий пользователя, молчит. Поэтому живость — по процессу, а не
по тишине.

## Что горит, когда программа не показывает статус

При выходе из программы, на паузе («Приостановить индикацию»), при завершении сеанса Windows и при удалении
подсветка получает эффект статуса «Нет активных сессий» — по умолчанию она **выключается**. Хочешь вместо этого
свою подсветку — выбери для «Нет активных сессий» эффект «Исходная подсветка»: программа при первом подключении
к OpenRGB запоминает режим и цвета каждого устройства и вернёт их. Запомненное живёт в памяти процесса: если
программа была убита посреди мигания (например, Диспетчером задач), при следующем запуске «исходной» станет мигание —
поправь цвет в OpenRGB и перезапусти программу.

Если программа завершилась аварийно, подсветка остаётся в последнем статусе до следующего запуска: убитый процесс
ничего не успевает отправить в OpenRGB.

## Постоянный свет

Устройства из списка «Постоянный свет» в индикации не участвуют: при каждом подключении к OpenRGB
программа ставит им один эффект (`fixedDevices`, `fixedEffect` в `settings.txt`). Пример — погасить
подсветку материнской платы: у некоторых контроллеров нет режима Off, тогда ставится Static с чёрным
цветом. Плата после перезагрузки возвращает свой сохранённый режим, поэтому держит её именно
AgentGlow; при выходе эти устройства не восстанавливаются. Тусклый нейтральный вместо
выключения — «Ровный цвет» и тёмно-серый, например `#202020`.

## Пересканирование OpenRGB

При пересканировании (подключили устройство, кнопка Rescan) OpenRGB меняет номера устройств и шлёт
уведомление «список изменился». Программа проверяет его раз в 15 с, перечитывает список и заново
применяет индикацию и постоянный свет. Новые устройства попадают в списки настроек.

Устройство, которого нет в OpenRGB, программа не видит: список поддерживаемого — на сайте OpenRGB.

## Эффекты

**Бегущая строка** — программный эффект: лента погашена, по ней бежит яркий сегмент с затухающим хвостом в 5
диодов. Круг по скорости 1–5: 2,4 / 1,8 / 1,2 / 0,9 / 0,6 с.

**Плавная пульсация** — программный эффект: карта в режиме Direct, программа 25 раз в секунду меняет
яркость по синусоиде от 100 % до 20 % — свет не гаснет. Период по скорости 1–5: 3,2 / 2,4 / 1,8 / 1,3 /
0,9 с. Таймер кадров (40 мс) работает только пока горит программный эффект.

Остальное — встроенные режимы контроллера (анимацию крутит сама карта, CPU не тратится). Встроенные
Breathing и Flashing у некоторых контроллеров (например, ENE на видеокартах ASUS) гасят диоды полностью,
поэтому по умолчанию не используются. Набор режимов и диапазон скорости у каждого устройства свои —
OpenRGB отдаёт их сам. Уровень скорости 1–5 в настройках раскладывается линейно на диапазон устройства. Режима
нет у устройства — берётся Static.

## Трей

- Значок — кружок цвета текущего статуса (серый — эффект без цвета или пауза).
- Проблемы самой программы видны только на значке, в подсветку они не попадают: подсветка показывает только
  состояние агентов. Кольцо с красной меткой «!» — проблема: нет связи с OpenRGB или он не отвечает, занят порт
  приёма событий, не подключена интеграция включённого источника; что именно — в подсказке и меню. Кольцо с
  мигающей оранжевой меткой-стрелкой — программа сама устраняет проблему (перезапускает службу OpenRGB).
- Двойной клик — настройки. Правая кнопка — статус, связь с OpenRGB, состояние интеграций, список тредов всех
  приложений («проект (приложение, …хвост id) — статус»); «Приостановить индикацию», «Сбросить статусы сессий»;
  «Настройки…», «Журнал», «Запускать при входе в Windows», «Проверить обновление…», «О приложении…»; «Выход».
- Настройки: эффект / цвет / скорость на каждый статус и кнопка «Проверить» (5 с), устройства
  (ничего не отмечено — все видеокарты), таймауты, порт приёма событий (после перезапуска; хуки и плагин
  прописаны с портом, поэтому после смены порта подключи интеграции заново — меню трея), автозапуск OpenRGB
  (только когда OpenRGB не установлен службой: службу программа перезапускает сама, см. «Грабли»).

## Автозапуск

- AgentGlow: ключ `HKCU\...\Run\AgentGlow` — включается галочкой в установщике, переключается в
  трее. Программа работает без прав администратора, поэтому ключ Run, а не задача Планировщика.
- OpenRGB: программа сама запускает `OpenRGB.exe --startminimized --server`, если не может
  подключиться и процесса OpenRGB нет (не чаще раза в минуту). Путь — `openRgbPath` в `settings.txt`.
- Фирменные программы подсветки (ASUS Aura `LightingService`, MSI Mystic Light, iCUE и т.п.) лучше
  отключить — иначе перебивают цвета.
- Если OpenRGB стоит службой Windows, запуск из программы не нужен и не срабатывает.

## Грабли

**После переустановки драйвера видеокарты смена режима молча не работает.** Симптом: бегущая строка
и пульсация горят (покадровая запись цветов проходит), а переход на ровный цвет не происходит —
подсветка замирает на последнем кадре. OpenRGB принимает команду смены режима, но активный режим
устройства не меняется, ошибок нет ни в одном журнале. Лечение — перезапустить службу из PowerShell
от администратора: `Restart-Service OpenRGB`. Программа переподключится сама.

**Служба OpenRGB перестала отвечать.** Симптом: подсветка замирает. OpenRGB принимает соединение, но не
отдаёт список устройств, а штатная остановка службы застревает в `StopPending`. Программа лечит это сама:
если служба OpenRGB не отвечает или не работает 30 секунд подряд, она перезапускает её и, когда та не
останавливается за 10 секунд, завершает её процесс. Перезапуск идёт через задачу Планировщика
«AgentGlow OpenRGB restart» с наивысшими правами: она запускает сам AgentGlow с ключом
`/restart-openrgb`, без окна консоли — её создаёт установщик, поэтому окна UAC нет. Не чаще раза в 10 минут. Пока
идёт перезапуск, значок в трее мигает, в подсказке и меню — «OpenRGB: перезапускаю службу…», в начале и в конце
приходит уведомление; каждый шаг — в журнале. Задачи нет (OpenRGB поставлен позже программы или учётная запись без
прав администратора) — приходит уведомление, по клику на него служба перезапускается через окно UAC. То же
вручную — пункт меню «Перезапустить службу OpenRGB» или PowerShell от администратора:
`Stop-Process -Name OpenRGB -Force; Start-Service OpenRGB`.

**OpenCode не шлёт события.** Симптом: подсветка не реагирует на OpenCode, в журнале нет строки
`opencode: plugin connected`. Проверь по порядку: в меню трея «OpenCode: подключено»; OpenCode перезапущен после
установки; в журнале нет строки «порт … занят»; в `~\.config\opencode\plugins` лежит `agentglow.js` с первой строкой
`// AgentGlow plugin version=2 port=47651`. Если задана переменная `XDG_CONFIG_HOME`, OpenCode читает плагины
оттуда — программа это учитывает. Первое событие нового процесса OpenCode теряется (`session.created` приходит
раньше подписки плагина) — ни на что не влияет, следующие события сессию подхватывают.

**Claude Code не шлёт события.** Симптом: подсветка не реагирует на Claude Code. Проверь: в меню трея
«Claude Code: подключено»; Claude Code перезапущен после установки (хуки читаются при старте); в журнале нет строки
«порт … занят». Хуки действуют на все сессии Claude Code, поэтому программа не меняет в `settings.json` ничего,
кроме своих хуков.

## Файлы

Программа — в папке установки (по умолчанию `C:\Program Files\AgentGlow`), данные — в
`%LOCALAPPDATA%\AgentGlow`:

- `settings.txt` — настройки (`key=value`, UTF-8).
- `sessions.txt` и `sessions-opencode.txt` — статусы тредов Claude Code и OpenCode; переживают перезапуск
  программы, при загрузке треды с завершившимся процессом отбрасываются.
- `log.txt` — журнал: запуск (версия, настройки, порт, интеграции, OpenRGB), события приложений (с префиксом
  источника), связь с OpenRGB, ошибки, при падении — её полный текст (при 512 КБ переезжает в `log.old.txt`).

Хуки — в `~\.claude\settings.json`, плагин — `~\.config\opencode\plugins\agentglow.js`.

## Сборка

Штатный `csc` .NET Framework 4.8, C# 5, без SDK и NuGet.

```
build.cmd nostart     программа → AgentGlow.exe
build-installer.cmd   программа, деинсталлятор и установщик → dist\AgentGlowSetup.exe
```

Без `nostart` скрипт запускает программу, и обёртка, вызвавшая `.cmd`, висит до её закрытия. Файл плагина
`plugin\agentglow.js` вшивается в программу и установщик ресурсом.

## Как подключить приложение

### Без кода: через `/status`

Любое приложение, которое умеет выполнять команду или HTTP-запрос на свои события (хуки, скрипты, обёртка над
запуском), подключается запросом на `/status`:

Из PowerShell:

```
Invoke-RestMethod -Uri http://127.0.0.1:47651/status -Method Post -Headers @{ "X-AgentGlow" = "1" } -ContentType application/json -Body '{"app":"codex","session":"abc123","status":"working","project":"D:/work/demo","pid":1234}'
```

Из Git Bash (в PowerShell и cmd вызывай `curl.exe`, а кавычки в JSON экранируй):

```
curl -s -H "X-AgentGlow: 1" --data-binary '{"app":"codex","session":"abc123","status":"working","project":"D:/work/demo","pid":1234}' http://127.0.0.1:47651/status
```

| Поле | Что |
|---|---|
| `app` | имя приложения; показывается в меню трея |
| `session` | номер сессии: один тред — один номер |
| `status` | `working`, `done`, `question`, `permission`, `error` или `ended` (закрыть тред) |
| `project` | папка проекта (показывается только её имя); необязательно |
| `pid` | номер процесса приложения; необязательно — по нему тред закрывается, когда процесс завершился |

Статусы те же, что и у остальных приложений, цвета и эффекты — общие. `question`, `permission` и `error` держатся
до следующего события этой сессии, поэтому **передавай `pid` и шли `ended`, когда сессия закончилась**: иначе
такой статус горит до закрытия треда по времени (12 часов) или до «Сбросить статусы сессий» в меню. Тред без
событий «Работаю» дольше `workingTimeoutMinutes` сбрасывается, «Закончил» — после `doneTimeoutMinutes`. Не более
200 тредов одновременно; переводы строк и прочие управляющие символы в полях заменяются пробелами.

Проверка без приложения — те же запросы руками:

```
printf '%s' '{"session_id":"t1","cwd":"D:/x","hook_event_name":"Notification","notification_type":"permission_prompt"}' | curl -s --data-binary @- http://127.0.0.1:47651/hook
curl -s -H "X-AgentGlow: 1" --data-binary '{"kind":"busy","sessionId":"ses_demo","pid":1234,"directory":"D:/x/demo"}' http://127.0.0.1:47651/opencode
```

### Свой источник: когда нужна логика приложения

Если у приложения хитрые события (как у Claude Code с агентами и разрешениями), заводится источник:

1. Папка `src\Sources\<Приложение>\`: класс, реализующий `IAgentSource` (разбор события, список тредов, таймауты,
   живость процессов, сохранение тредов), и при необходимости класс `IIntegration` (как прописать хуки или плагин).
2. Одна строка в `SourceCatalog.All`. Из каталога сами строятся галочка в установщике, шаг деинсталлятора, блок в меню
   трея, ключ `sources` и префикс источника в журнале.
3. Состояние источник выражает через общие статусы (`GlowStatus`): своих статусов и своих цветов у него нет.

Адрес приёма (`Route`) источник выбирает себе сам; заголовок `X-AgentGlow` обязателен, если не задано `RequiresMarker =
false`.
